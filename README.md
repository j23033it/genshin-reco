# ビルドレコメンダー

知りたい4人だけを会話から調査し、結果をカードとして保存する原神／崩壊：スターレイル向けデスクトップアプリです。

最初からゲーム情報をすべて同梱しません。Codex App Serverが会話から4人と任意条件を整理し、必要な情報だけをWeb調査します。Rust側は入力、根拠URL、目標ステータス、保存内容を検証し、会話・完成編成・再利用可能な調査断片をSQLiteへ保存します。

## 開発環境

- Tauri v2
- React 19 / TypeScript / Vite
- Tailwind CSS v4 / Base UI
- Rust stable（MSVC）
- Vitest

## コマンド

```powershell
npm install
npm run dev
npm run test
npm run build
./scripts/use-cargo-target.ps1
npm run tauri dev
npm run check
```

Rust/Tauriを使うPowerShellでは、`tauri dev`や`check`の前にビルド先設定を一度実行する。作業フォルダごとに別のビルド先を選ぶため、移動前の絶対パスを持つ古い生成物を再利用しない。

## 基本の流れ

1. 調べたい4人を自然文で入力する。名前が足りなければCodexが聞き返す
2. 4人の凸と武器（スターレイルは光円錐）を画面で選ぶ。一覧のスクロールに加え、名前で検索できる。キャラクターの武器種・運命に合う候補だけを表示する。検索のクリアやEscで全候補に戻り、検索中も選択済みの装備を保持する。未確定なら「指定なし」のまま進める
3. 調査の進捗を会話内に表示する
4. 調査に成功した編成だけを保存する
5. 保存結果をキャラクター・武器・聖遺物・目標ステータスのカードで表示する
6. 同じ会話を開き直し、条件変更後に再調査する

## 過去の調査の再利用

- 新しい会話で調査するとき、過去7日以内に同じ4人・武器・命ノ星座・精錬で調べた結果があれば、Web調査を省いて再利用する。4人の並び順と編成名は一致しなくてもよい。「指定なし」は具体的な指定と区別する。
- ゲーム版、同梱カタログ、調査の指示・モデル・出力形式・出典ルールが変わった結果は、そのまま再利用しない。再利用した結果には案内を表示する。
- 条件が違う場合も、同じゲーム版で直近7日以内に確認したキャラクター・武器の出典を調査の手がかりにする。別編成の数値を引き継がず、本文を開いて今回の条件に合うか確認し直す。
- 保存済み編成の「条件を変えて再調査」から始める調査は、同じ条件でもWebで確認し直す。
- 再利用しても元の調査日時は更新しない。完成編成と再利用データは同時に保存し、失敗やキャンセルの結果は再利用対象に追加しない。導入前の保存結果は出典の手がかりとして利用でき、完成結果の再利用は導入後の調査成功から有効になる。

## 情報収集の進め方

- 原神Wiki、Game8、HoYoWiki、GameWithの個別本文を調査対象にする。GameWithは原神の記事ページに限定し、毎回全サイトを読むことは求めない。[追加時の比較記録](docs/research/gamewith-2026-09-27/comparison.md)には所要時間、使った出典、数値確認と限界を記録している。
- 編成調査は`gpt-6-sol`を使い、資料収集は`medium`、最終検討は`low`、両方Fastで実行する。検索量は`low`、本文取得は`live`を維持する。Fastは編成調査の会話だけに適用し、受付はWebなしの通常モードで行う。[実装と実調査の検証記録](docs/research/source-selection-2026-09-28/verification.md)を残している。
- 保存済みの出典本文を先に確認し、足りないキャラクターのビルド検索を2〜4件ずつまとめる。検索結果は少量に絞り、本文は各対象の上位1〜2件から読む。
- 武器・天賦・命ノ星座の追加検索は、先に読んだ本文では足りない事項だけに絞る。4人で共通する武器・聖遺物の根拠は共有する。数値や発動条件が足りなければページを追加で確認する。
- 読んだ本文の数値・発動条件・出典を短く整理し、閲覧済みURLの一覧と一緒に次の検討へ渡す。最終出典のURLはこの一覧から選び、未閲覧の資料や検索結果の要約を根拠にしない。検討中に追加で開いた資料は、閲覧履歴からURLを一度だけ確定する。数値や説明は変更せず、対応する本文がなければ失敗として扱う。
- 資料収集と編成検討の時間・Web完了イベント数・閲覧URLの記録数を開発時のログへ残す。速くなったかは同じ編成・条件で比較し、根拠検査の成功も一緒に確認する。URLの確認は数値の読み取りや出典と主張の対応まで自動保証するものではない。

## デスクトップ版と試運転版

- 日々の画面確認は `npm run dev` の `http://localhost:1420/?demo=1` で行う。固定のデモデータだけを使い、実際の調査・保存・更新は行わない。
- 調査と保存の動作確認は、実処理を呼ぶスクリプトでも行える。スターレイルは `pwsh ./scripts/verify-star-rail-live.ps1 -DatabasePath <SQLiteの絶対パス> -CodexHome <アプリ専用の認証済みホーム> -ReportDirectory <記録先>` を使う。アプリと同じCodex App Serverによる実Web調査、条件固定・解除、実保存、別プロセスでの読込、キャンセル・通信切断時の結果保持、同条件の再利用を確認する。通信中断の確認用ターンは検索を無効にする。指定DBへ検証用の会話と編成を保存するため、アプリを終了して実行する。
- 保存だけを確認するときは、`-ResultDirectory <確認済み出力の置き場>` を追加する。`mixed.json`・`fixed.json`・`released.json` に `intake`・`output`・`openedUrls`・`verificationKind` を渡す。確認方法はアプリ実出力なら `app_observation`、作業者が本文を照合した検証用出力なら `operator_verified_fixture`。後者は自動調査の成功として扱わず、調査結果の再利用候補へ保存しない。
- 画面を含む開発アプリの確認は `npm run tauri dev` で行う。この開発版から正式版の更新はしない。
- 正式版はWindows用インストーラーで一度だけ導入する。デスクトップにアプリのショートカットができ、以後はアプリ内の「更新を確認」から署名済みの新しい版を導入する。
- ソースと変更履歴、署名済みインストーラー、`latest.json` は、公開リポジトリ [j23033it/genshin-reco-releases](https://github.com/j23033it/genshin-reco-releases) でまとめて管理する。既存アプリの更新先URLを保つため、リポジトリ名は変更しない。デモや開発版は更新しない。
- 以前の非公開リポジトリ `j23033it/genshin-reco` は削除済み。今後の開発と公開は統合先で行う。

## 崩壊：スターレイル

ヘッダーでゲームを選び、4人を送信して星魂・光円錐・重畳と任意の固定遺物を指定する。トンネル遺物は指定なし／4セット／異なるセットの2＋2、オーナメントは指定なし／2セットを選べる。指定したセットは維持し、未指定部分だけを編成全体に合わせてWeb調査で提案する。同じセットを複数人に指定できる。実物ステータスや所持数は入力しない。

結果ではトンネルとオーナメントを分け、「指定を維持」「自動提案」、採用理由、発動条件・注意点、出典、戦闘前の目標値を表示する。目標値は実測値や条件達成の保証ではない。保存した会話で再調査するときも、提案値を元の未指定欄へ固定しない。

スターレイルの調査領域は原神で使用している4サイトの各ゲーム領域に限定する。旧原神データは原神として移行し、ゲームごとの会話・入力途中状態・一覧・キャッシュを分離する。処理中のゲーム切替は理由を表示して制限する。

名称カタログは2026-10-04に正式公開版4.6までを照合し、93キャラクター形態・170光円錐・34トンネル遺物・28オーナメントを正式候補として収録した。実在対象を確認できない旧装備2件は保存済みの指定を保持し、再調査時に再選択を求める。画像は未登録なら名称で表示する。収録範囲と照合元は [4.6検証記録](docs/research/star-rail-2026-10-04/verification.md)、更新方法は [カタログ更新](docs/catalog-updates.md)、保存・検証の契約は [設計資料](docs/architecture.md) を参照。

この一覧の収録版は調査する版ではない。現在の本文を確認し、版番号を確定できなければ「不明」と表示する。同条件の最長7日の結果を再利用する場合も元の調査日時を維持する。最新情報を取り直す場合は保存結果から再調査する。[ローカルでの実調査・保存・再起動の検証記録](docs/research/star-rail-2026-10-01/verification.md)も参照。

## アプリ表示名と互換性

画面・ウィンドウ・Windowsのアプリ一覧とショートカットの表示名は「ビルドレコメンダー」。既存インストールを同じアプリとして検出するため、Tauriの `productName` は内部の配布名「原神 聖遺物レコメンダー」のまま維持する。NSISのセットアップ画面と既定インストールフォルダーにはこの旧名が残る。表示名・ショートカット名は `src-tauri/windows/hooks.nsh` で更新する。

`jp.taiki.genshinreco`、SQLiteの保存先・ファイル名、実行ファイル名、アップデートURL、署名鍵、版番号はこの改名では変更しない。Windowsでのインストール・旧版からの更新・実データの引き継ぎは別途確認が必要。
