既存の実調査テストに`GENSHIN_RECO_SERVICE_PROFILE=fast`の切り替えを追加した。指定しない場合は通常モードのまま。各実行で`config/read`のFast指定、Fastの有効化、検索量、対象ドメインを確認し、その値をJSONへ保存する。認証情報や一時ホーム内のデータは保存しない。アプリ本体の既定値と正式版は変更しない。

[OpenAIの公式資料](https://learn.chatgpt.com/docs/agent-configuration/speed)に従い、`service_tier = "fast"`と`features.fast_mode = true`を両方指定する。GPT-6 LunaのFastは利用可能な環境で通常の2.5倍のクレジット消費とされる。これは公式の消費条件であり、今回の実行だけの消費量を実測した値ではない。

時間の計測範囲は前回と同じ。資料収集時間は設定確認と会話開始を含み、比較用のURL転記修正は含まない。完成編成の全体時間には資料収集、最終検討、必要なURL修正を含む。プロセス初期化とビルドは含まない。閲覧イベント数は通信回数とは区別する。

同じ1編成の小数回の試験であり、前回と今回は実行日時が異なる。検索結果、サービスの混み具合、回答の揺れ、本文の変更は完全には揃えられない。Fastの指定値は確認するが、個々の推論が実際にどの速度で処理されたかをサービス側の記録から確認するものではない。

### 完成結果の内容確認

Fast1ではベネットLv.90の191と原木刀Lv.90の565の合計756、1凸のHP制限撤廃と基礎攻撃力20%分の追加、未解放の2凸チャージ効率+30%の除外を正しく説明した。夜蘭の固有天賦は炎・水・岩の3種類でHP+18%、水共鳴+25%を含めない。千岩牢固2セットHP+20%と4セットの攻撃力+20%・シールド強化+30%・継続3秒も分けた。鍾離の近くの敵への耐性-20%は通常の完成結果より具体的に記載された。

ただし、鍾離のHP目標48,000〜53,000の下限48,000は、本人が置いたLv.90・武器Lv.90・聖遺物+20・HPメイン3部位・千岩2セットの装備計算からは導けない。[鍾離の基礎HP14,695](https://wikiwiki.jp/genshinwiki/鍾離)、黒纓槍のHP46.9%、[星5+20のHPメイン46.6%と花4,780](https://wikiwiki.jp/genshinwiki/聖遺物)、千岩2セットHP20%を使うと、サブ効果なしでも14,695×(1+0.469+3×0.466+0.20)+4,780=49,849.565となる。条件を維持するなら実際の画面値は約49,850以上であり、48,000は同じ装備条件で到達する画面値ではない。範囲内の49,850〜53,000は可能なので提案全体が成立しないとはしないが、実用目安と厳密な装備計算の区別が粗い。通常の50,000〜54,000にはこの下限の食い違いはない。

同じ観点では、通常とFast1の夜蘭チャージ効率220〜240%も、主効果にチャージ時計を指定する一方で厳密な装備計算より広い目安である。Lv.90西風猟弓・絶縁2セット・星5+20チャージ時計ならサブ効果前に100+61.3+20+51.8=233.1%。220%をその装備の実際の画面値とは扱えない。このような目標の粗さは通常にもあり、Fastだけが生んだ精度悪化とは断定しない。

Fast1はアルレッキーノを攻撃力杯にし、攻撃力目標を通常の1,900〜2,200から2,200〜2,500へ変えた。与ダメージ効果が多いという理由は付くが、同じ聖遺物のサブ効果・天賦・攻撃手順で炎杯と比較したダメージ計算はないため、最適さの改善とは扱わない。夜蘭HPも24,000〜28,000から26,000〜30,000へ変わる。基礎値と反応条件の事実確認と、裁量が入る目標・装備提案の比較を分ける。

西風猟弓の出場条件と12秒間隔、アルレッキーノの戦闘中炎ダメージ+40%と外部回復制限、原木刀の葉が今回の4人だけでは発動しないことは、Fast1の完成結果に明記されない。原木刀の熟知+60を数値目標に加算する誤りは見当たらないが、説明不足は残る。資料収集だけの実行と完成までの実行は別会話で、完成回の資料整理JSONは保存していない。資料収集単独の誤記が同じ会話の最終検討で訂正されたことを証明するものではない。

Fast2では、白纓槍の精錬5が通常攻撃+48%、アルレッキーノの戦闘中炎ダメージ+40%と断章与ダメージ+54%を表示杯46.6%から分けること、夜蘭の3元素HP+18%、西風精錬1の会心時60%・エネルギー6・12秒間隔、絶縁の220%×25%=爆発ダメージ+55%を水元素ダメージ表示へ足さないことを正しく説明した。ベネットの基礎攻撃力756と、チャージ効率100+26.7+30.6+51.8=209.1%の計算も合う。

しかし、Fast2のベネットのチャージ効率注記には「元素爆発の必要エネルギーは80」と明記された。正確には[60](https://wikiwiki.jp/genshinwiki/ベネット)。資料収集単独の2回にも出た誤りが、別会話の完成結果でも出ている。出典URLと構造の検査が通ったことを、全ての数値の正確さとして扱えない。

Fast2は鍾離を千岩牢固2セット＋花海甘露の光2セットへ変更し、HP+40%を使った。14,695×(1+0.469+3×0.466+0.40)+4,780=52,788.565で、注記の「サブHP前に約52,800」は一致する。HP目標52,000〜56,000の下限52,000は、その注記の装備計算より低い概算目安。夜蘭はHP時計へ変更してHP28,000〜33,000を提案し、チャージ不足なら時計を交換しHP低下を許容すると説明する。これらは装備方針の変更であり、精度や最適さの改善の証明とはしない。

Fast2でも西風猟弓の装備者出場条件、アルレッキーノの外部回復制限、ベネット1凸の追加20%の説明、原木刀の今回の不発条件、鍾離の耐性低下の具体的な20%は明記されない。誤った発動や未解放の凸を数値目標へ加算する主張は見当たらないが、条件説明の抜けは残る。

## 確認と後片付け

`npm run check`は成功。フロントエンド109件、Rustライブラリ140件、取込処理3件のテストと、静的検査・ビルドが通った。Fast1完成の最終検討待ちに一括検査も実行したため、その回はローカルPCの検査処理も同時に動いた。Fastの試験同士は同時に実行していない。時間の差からFast以外の要因を完全には除去していない。

試験の4つの一時ホームを削除した。削除前に絶対パス、一時フォルダ内であること、再解析ポイント0件、その一時ホームを使うプロセス0件を確認した。認証情報のコピー4件も含めて削除し、元のアプリ用ホームと個人用ホームには変更を加えていない。アプリ本体の`service_tier = "default"`、`fast_mode = false`も確認した。試験用の指定は一時ホームと試験プロセスだけであり、利用中のCodexチャットの設定を切り替えたとは報告しない。

`git diff --check`も成功。既存変更を残したまま現在の`main`で進め、一時ブランチ・worktreeは作成していない。最後にworktreeとローカル・リモートブランチを確認し、追加の作業用ブランチ・worktreeがないことを確認した。コミット・プッシュ・公開はしていない。

## 正式版への採用判断

今回は正式版へFastを導入しない。ユーザーが結果を見て判断するための試験であり、アプリ本体の通常モードを変更せず、正式版の公開も行わない。

この1編成では速度の利点が見えた。資料収集の各2回で約29%、完成結果のFast2回と通常1回で約39%の短縮を観測し、Fastの完成2回とも出典と構造の検査に通過した。一方、資料整理の網羅性の改善はなく、完成結果にもベネットの必要エネルギーの誤記が残った。通常の完成結果にも表現や条件説明の不足があり、試行が少ないためFastが誤記を増やしたという因果関係は断定しない。品質が同等と確認できたとも言えない。

うちの見立ては、短縮のメリットはあるが、正式版の既定をFastへ変える判断はいったん保留。公式の通常2.5倍のクレジット消費に対して、今回の全体短縮は約39%だった。実行ごとのトークン量とクレジット消費は測定しておらず、今回の総消費が厳密に2.5倍だったと判断する比較ではない。速度を重視して採用する場合も、事実の取り違えと説明不足への対応は別に残る。
