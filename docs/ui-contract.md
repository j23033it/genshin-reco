# オンデマンド編成調査 UI 契約

更新日: 2026-09-25

## 目的

ユーザーが自然文で指定した4人だけをCodexで調査する。初期状態は空とし、成功した編成だけを保存一覧へ追加する。

## 画面の流れ

1. 空の会話で「調べたい4人」を入力する。
2. 4人未満ならCodexが不足している名前だけを聞き返す。
3. 4人が揃ったら、未指定の武器・命ノ星座・精錬を示しつつ、そのまま調査開始できる。
4. 調査中は現在工程を同じ会話内へ表示し、キャンセルできる。
5. 成功時だけ保存一覧へ追加し、4人分のカードを表示する。
6. 保存編成を開くと同じ会話を復元し、条件を追加・変更して再調査できる。

## 状態

- `collecting`: 4人を集めている。
- `ready`: 4人が揃い、調査を開始できる。
- `researching`: 調査中。送信と二重開始を無効にする。
- `succeeded`: 最新の成功結果を表示する。
- `failed`: 入力を残し、再送信または再調査できる。
- `cancelled`: 入力を残し、再調査できる。

非同期応答と進捗イベントは`sessionId`が現在表示中の会話と一致する場合だけ反映する。

## 結果カード

各キャラクターへ次を表示する。

- キャラクター名、元素、役割、命ノ星座、画像
- 武器名と画像
- 聖遺物名と画像
- 砂・杯・冠のメインステータス
- サブステータス優先度
- 2〜8件の目標ステータスと、値に関係する注意点

目標ステータスには、会心や元素ダメージだけでなく、攻撃力、HP、防御力、元素熟知、基礎攻撃力など役割の計算元になる値を最低1件含める。これを`primary: true`として「主参照」で強調する。

元素共鳴、固有天賦、武器、聖遺物、命ノ星座、味方の効果が目標値に影響する場合は、対象の値のそばに適用条件と戦闘前・戦闘中の扱いを示す。会心率は条件付き加算を含めた上限にも注意する。既存の保存結果に注意点がない場合は、再調査を促す案内を示す。

画像が取得できない場合もカードを壊さず、名称の先頭文字を代替表示する。画像だけで意味を伝えない。

## バックエンド契約

- `send_on_demand_message({ sessionId?, message })`
- `start_on_demand_research({ sessionId })`
- `cancel_on_demand_research({ sessionId })`
- `list_researched_teams()`
- `load_researched_team({ teamId })`
- `load_on_demand_conversation({ sessionId })`
- event: `on-demand-research-progress`

進捗イベントは`{ sessionId, stage, detail, memberName? }`を返す。

## 操作と表示

- 送信・調査開始・キャンセルはネイティブの`button`で操作できる。
- 二重送信、二重調査、キャンセル後に届いた古い応答を反映しない。
- エラーは操作箇所の近くへ日本語で表示し、入力を消さない。
- デスクトップは左に保存一覧、中央に会話または結果を置く。狭幅では縦に並べ、横スクロールを作らない。
- 既存のダークテーマと琥珀色アクセントを保つ。グラデーションや過剰な発光は追加しない。

## 完了条件

- 空状態から4人指定、質問、調査、保存、結果表示まで進める。
- 保存編成から会話を復元し、条件変更後に再調査できる。
- 各カードに主参照の目標ステータスがある。
- 画像・目標値・根拠が欠けても安全な代替表示またはエラーになる。
- lint、型検査、UIテスト、build、Rustテストが通る。
