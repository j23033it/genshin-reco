### 確認元と対象範囲

- [公式のVer.7.1祈願告知](https://genshin.hoyoverse.com/m/ja/news/detail/166228)で、新キャラクター2人と祈願武器5種の日本語名・元素・武器種・レアリティを、記載のある範囲で照合した。
- [Project Amberの版別変更一覧](https://gi.yatta.moe/api/v2/static/changelog?vh=71F2)の `version: 7.1` を追加対象の確認に用いた。
- [キャラクター一覧](https://gi.yatta.moe/api/v2/JP/avatar?vh=71F2)、[武器一覧](https://gi.yatta.moe/api/v2/JP/weapon?vh=71F2)、[聖遺物一覧](https://gi.yatta.moe/api/v2/JP/reliquary?vh=71F2)で、名称・分類・画像識別子と既存データとの差分を確認した。Project Amberは非公式のゲームデータベース。
- APIの言語指定は `JP` を使用する。確認時、`jp` ではVer.7.0相当の古い一覧が返った。サイトが使う版指定 `vh=71F2` も明記する。
- 新規8件の画像はAPIに記載された画像識別子からURLを作り、全件でHTTP 200・`image/png`・空でない本文を確認した。
- 版別一覧にある武器ID `390002`・`390003` は `isWeaponSkin: true` の外見データなので、装備候補の武器一覧には追加しない。
- Ver.7.1の聖遺物セット追加はない。既存63セットの効果文も、改行表現を正規化すると取得した一覧と一致する。
- このカタログの対象はキャラクターの基本分類、武器の基本分類、聖遺物セット効果と画像。天賦倍率・武器効果など、元の形式にない情報は含まない。

### 再生成

`public/data/sources` の3ファイルを編集し、`import_catalog` でJSONとmanifestを再生成する。`src-tauri/src/catalog.rs` の件数・元ファイルのSHA-256もmanifestに合わせる。Rustコマンドの前には、プロジェクトルールに従って `scripts/use-cargo-target.ps1` を実行する。

## スターレイル

`public/data/star-rail/catalog.json` は `star-rail-catalog-v1` の独立した名称カタログ。キャラクターの別形態・属性・運命、光円錐の運命、トンネル遺物、オーナメントを分ける。初期スナップショットは3.0までの代表的な名称を収録し、全キャラ・全装備や最新版の網羅を保証しない。カタログは効果や基礎数値の図鑑ではない。新しいキャラ・装備・別形態はここへ正式名称で追加する必要がある。曖昧な略称は受付で確認する。

更新時は許可されたスターレイル領域（WIKIWIKI `/star-rail/`、Game8 `/houkaistarrail/`、GameWith `/houkaistarrail/`、HoYoWiki `/pc/hsr/` または `/m/hsr/`）で名称と運命を確認し、`gameVersion` と `catalogUpdatedAt` を合わせて更新する。HoYoWikiの取得に失敗した場合も、他ゲームのページや別サイトへ切り替えない。取得できた個別本文のURLを検証記録に残す。

2026-10-01の部分修正では収録範囲 `3.0` は維持し、確認日だけを更新した。「逃げ場なし」「天傾」の誤表記を直し、彦卿・ルカ・雲璃・ブラックスワンを補った。照合元の個別本文は[検証記録](research/star-rail-2026-10-01/verification.md)を参照。最新版の全件収録を意味しない。

2026-10-04の更新では正式公開版 `4.6` までの公開済み名称を全件照合した。正式候補は93キャラクター形態・170光円錐・34トンネル遺物・28オーナメント。初期カタログから28形態・129光円錐・10トンネル・9オーナメントを追加し、「愉悦」の運命と開拓者の新形態にも対応する。旧ID・名称は保持する。対象を特定できない「瞬間を記憶に留めて」「悠久の地アムフォレウス」は `legacyOnly: true` で保存専用として残し、新規候補から外して再選択を求める。JSON総数171光円錐/29オーナメントと正式候補数を混同しない。全件の名称・分類・取得した本文URL、表記差の判断は[4.6検証記録](research/star-rail-2026-10-04/verification.md)と[独立照合一覧](research/star-rail-2026-10-04/reference-inventory.json)を参照。

以後の更新では `validate_catalog_inventory` が参照する照合記録も、外部本文から確認して更新する。件数を合わせるだけでなく正式候補の全件集合・属性・運命を一致させる。保存専用の名称は別の実在対象へ推測で移行しない。

`gameVersion` はこの名称一覧の収録範囲であり、実調査する版ではない。資料収集・最終検討へは名称・属性・運命・カテゴリの選択肢だけを渡す。調査結果の版と効果は調査日の個別本文で確認し、旧性能の章との混同を避ける。最新版の名称追加を行う場合に初めて収録範囲を更新する。

スターレイルの結果再利用では名称一覧の版で絞らず、実調査で最後に保存された本文の版と一致する、同じ条件・調査仕様・名称一覧の最長7日の結果を使う。新しい版で調査したら以前の版の結果は候補から外す。結果に記録された本文の版（確定できなければ「不明」）は維持する。出典候補は個別ページのURLだけを渡し、本文を再確認する。保存済み編成からの再調査は必ずWebへ取り直しに行く。原神の版一致の条件は維持する。ルサカなどの配置依存の効果があるため、スターレイルのキャラ配置を入れ替えた場合も別条件として扱う。

画像は確認できた対応する項目のURLだけを登録する。初期カタログの画像は未登録（null）で文字の代替表示を使う。URLを推測して埋めない。トンネルとオーナメントの画像は独立して扱う。名称照合に失敗した固定指定は無言で削除されず、UIとRustが再確認を求める。

同時編成できない別形態には同じ `exclusiveGroup` を付ける。開拓者の各運命は `trailblazer`、三月なのかと巡狩形態は `march-7th`。丹恒と飲月のようにゲーム内で併用できる項目へこの制限を付けない。入力と保存前の結果で同じ排他関係を検査する。

`npm run check` の `catalog:check` は従来の原神カタログ検証に加え、Rustの `validate_star_rail_catalog` で名称カタログの型、ゲーム識別、ID・名称の空欄と重複、属性・運命、独立照合一覧との正式候補集合・分類・版・確認日の一致を検査する。Rustコマンドの前は `AGENTS.md` と同じPowerShellでビルド先を設定する。
